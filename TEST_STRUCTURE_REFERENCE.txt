QUICK COMMANDS
────────────────────────────────────────────────────────────────────────────────

Run tests for one service:
  $ cd api-gateway && pytest tests
  $ cd ingestion && pytest tests
  $ cd vector-store && pytest tests
  $ cd rag-engine && pytest tests
  $ cd embedding-server && pytest tests

Run only unit tests (fast, no external deps):
  $ pytest tests/unit

Run only integration tests (needs docker-compose up):
  $ pytest tests/integration

Run specific test file:
  $ pytest tests/unit/test_auth_middleware.py

Run specific test class/method:
  $ pytest tests/unit/test_auth_middleware.py::TestAuth::test_login

Run tests matching a pattern:
  $ pytest tests -k "auth"  # Run all tests with "auth" in name

Run with verbose output:
  $ pytest tests -vv

Run with short traceback:
  $ pytest tests --tb=short

Stop on first failure:
  $ pytest tests -x

Run in parallel (requires pytest-xdist):
  $ pytest tests -n auto

Show print statements:
  $ pytest tests -s

SETUP FOR FIRST TIME (Per Service)
────────────────────────────────────────────────────────────────────────────────

1. Create virtual environment:
   $ cd api-gateway
   $ python -m venv venv

2. Activate virtual environment:
   macOS/Linux:
   $ source venv/bin/activate
   
   Windows:
   $ venv\Scripts\activate

3. Install dependencies:
   $ pip install -r requirements.txt

4. Run tests:
   $ pytest tests

5. Run specific test type:
   $ pytest tests/unit      # Unit tests only
   $ pytest tests -m integration  # Integration tests only

TROUBLESHOOTING
────────────────────────────────────────────────────────────────────────────────

Problem: "ModuleNotFoundError: No module named 'src'"
Solution: Make sure venv is activated and you're in service directory
  $ cd api-gateway
  $ source venv/bin/activate
  $ pytest tests

Problem: "No tests ran" or "Cannot collect tests"
Solution: Check pytest discovers your tests
  $ pytest tests --collect-only

Problem: "ImportError" or "ModuleNotFoundError"
Solution: Verify requirements are installed
  $ pip list | grep pytest
  $ pip install -r requirements.txt

Problem: Connection errors in integration tests
Solution: Start docker-compose stack first
  $ docker-compose up -d
  $ pytest tests -m integration

Problem: Tests are slow
Solution: Skip integration tests, run unit tests only
  $ pytest tests/unit   # No external dependencies

CI/CD INTEGRATION (GitHub Actions)
────────────────────────────────────────────────────────────────────────────────

Each service runs independently in CI (can run in parallel):

.github/workflows/ci.yml should have separate jobs:

  jobs:
    test-api-gateway:
      runs-on: ubuntu-latest
      steps:
        - run: cd api-gateway && pip install -r requirements.txt
        - run: cd api-gateway && pytest tests

    test-ingestion:
      runs-on: ubuntu-latest
      steps:
        - run: cd ingestion && pip install -r requirements.txt
        - run: cd ingestion && pytest tests

    # ... similar for other services

Benefits:
  • Services run in parallel (faster)
  • Clear which service failed
  • Each service only installs needed deps
  • Can run ~2x faster than sequential

WRITING NEW TESTS
────────────────────────────────────────────────────────────────────────────────

Create test file: <service>/tests/{unit or integration}/test_<feature>.py

Example unit test:

  # api-gateway/tests/unit/test_my_feature.py
  import pytest
  from src.my_module import my_function

  class TestMyFeature:
      def test_something(self):
          result = my_function()
          assert result == expected

Example integration test:

  # ingestion/tests/integration/test_e2e.py
  import pytest
  
  @pytest.mark.integration
  class TestEndToEnd:
      async def test_document_processing(self, mock_kafka):
          from src.workers import process_document
          result = await process_document(...)
          assert result.success

Key points:
  ✓ No sys.path.insert() needed
  ✓ Import from src/ directly
  ✓ Use service's fixtures from tests/conftest.py
  ✓ Mark integration tests with @pytest.mark.integration

BENEFITS OF THIS STRUCTURE
────────────────────────────────────────────────────────────────────────────────

✅ Service Isolation     → Each service has only its dependencies
✅ No sys.path Hacks    → Clean imports like normal Python
✅ Faster Tests         → No loading unnecessary deps
✅ Parallel CI          → Run services in parallel (~2x faster)
✅ Clear Boundaries     → Know which test belongs where
✅ Better IDE Support   → Autocomplete works
✅ Easy Onboarding      → "cd <service> && pytest tests"
✅ Future-Proof         → Easy to add new services
